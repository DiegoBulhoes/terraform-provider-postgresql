# Resource (postgresql_role)

Manages a PostgreSQL role as a permission group. A role holds a set of privileges that you assign to users with `postgresql_user`.

~> **Note:** Roles created here always have `NOLOGIN`. For users that log in with a password, use `postgresql_user`.

## Inline `privilege` Blocks vs. Separate `postgresql_grant` Resources

You can attach privileges to a role in two ways:

| Approach | Pros | Cons |
|----------|------|------|
| Inline `privilege { }` blocks (this resource) | Short, and the privileges sit next to the role | No import per grant, no `with_grant_option`, and any change updates the whole role |
| Separate `postgresql_grant` resources | Each grant has its own lifecycle: plan, apply, import, drift check. Supports `with_grant_option` | Longer, and the grants sit far from the role |

Use inline blocks when the privileges are simple and change together. Use `postgresql_grant` when you need finer control, such as schema-level grants shared by many roles, or delegation with `with_grant_option`.

~> **Privilege validation.** Keywords in `privilege.privileges` are checked against the same allowlist as `postgresql_grant`. The [grant resource docs](grant) have the full list.

## Example Usage

```terraform
# Minimal: only "name" is required
resource "postgresql_role" "basic" {
  name = "basic_role"
}

# Role with inline privileges on all tables in a schema
resource "postgresql_role" "readonly" {
  name = "readonly"

  privilege {
    privileges  = ["SELECT"]
    object_type = "table"
    schema      = "public"
  }
}

# Role with multiple privilege blocks
resource "postgresql_role" "readwrite" {
  name = "readwrite"

  privilege {
    privileges  = ["SELECT", "INSERT", "UPDATE", "DELETE"]
    object_type = "table"
    schema      = "public"
  }

  privilege {
    privileges  = ["USAGE", "SELECT"]
    object_type = "sequence"
    schema      = "public"
  }
}

# Role with schema-level privileges
resource "postgresql_role" "schema_admin" {
  name            = "schema_admin"
  create_database = true

  privilege {
    privileges  = ["CREATE", "USAGE"]
    object_type = "schema"
    schema      = "public"
  }
}

# Role with database-level privileges
resource "postgresql_role" "db_connect" {
  name = "db_connect"

  privilege {
    privileges  = ["CONNECT"]
    object_type = "database"
    database    = "myapp"
  }
}

# Role with privileges on specific tables
resource "postgresql_role" "reports" {
  name = "reports"

  privilege {
    privileges  = ["SELECT"]
    object_type = "table"
    schema      = "public"
    objects     = ["orders", "products", "customers"]
  }
}
```

## Import

Import a role by its name:

```shell
terraform import postgresql_role.readonly readonly
```

Import does **not** recover inline `privilege` blocks. After an import, run `terraform plan`: the provider re-applies the `privilege` blocks from your config.
